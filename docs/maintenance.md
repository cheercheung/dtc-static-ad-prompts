# Maintenance

[Return to the library](../README.md)

## Canonical data and generated pages

`data/prompts.json` contains the complete 40 English prompt bodies, stable IDs,
case numbers, categories, titles, and empty subcategory values. The routing
manifest `data/content-layout.json` declares the six categories in order.
Locale dictionaries under `data/locales/` contain translated interface text and
all 40 case titles. Prompt bodies remain English in every language edition.

`README.md`, the ten `README_{locale}.md` pages, and all files under `cases/`
are generated. Edit the JSON data and rebuild; direct edits to generated pages
will be replaced. The separate usage guide is maintained as authored prose.

## Update procedure

1. Identify the case or interface field and its stable ID. Keep case numbers,
   category paths, and explicit anchors stable.
2. Propose any change to a preserved prompt body for separate review. Ordinary
   navigation and translation edits must leave every prompt body unchanged.
3. Update visible labels and titles in all applicable locale dictionaries with
   actual translations. Preserve the dictionary schema and stable IDs.
4. Rebuild and validate from the repository root with Python 3.10 or newer:

```
python3 scripts/build_library.py
python3 scripts/verify_library.py
python3 scripts/build_library.py --check
```

5. Review the diff, copy a rendered prompt back to plain text, and verify that
   its contents match the intended canonical body. Inspect navigation and code
   blocks at desktop and narrow widths before a release.
6. Keep all working evidence, review reports, source files, credentials, and
   private campaign briefs outside this library. Public licensing, repository
   creation, metadata, and publication decisions are maintained separately.

## Portable validation

The scripts use only Python's standard library and resolve paths from their own
location. A clean copy can rebuild and validate without the original extraction
folder, a global skill installation, network access, or local campaign files.
The validator checks canonical counts and IDs, generated byte equality, locale
schema, translated-title presence, path safety, page size, and local links.
These checks do not demonstrate ad performance or image-generation quality.

## Adding material

The first edition is fixed at 40 prompts. A later expansion needs an explicit
inventory and scope update, a decision about numbering and provenance, complete
localization, and fresh content and rendering review. Do not bypass the fixed
count by adding an unindexed category page.

## Static example images and the shared banner

`data/examples.json` declares the `owner-provided-r2-static-images` media policy
and unchanged `fenced` prompt presentation. Its 40 ordered entries bind each
canonical prompt ID, case number, and category to one main PNG. Case 37 also
binds one alternate PNG. Every output records only its role, public URL, SHA256,
width, height, and MIME type. The 41 original images are stored at the declared
repository namespace on R2; local source paths and upload evidence stay outside
the public repository.

`data/examples-ui.json` contains seven actual translated interface strings for
each of the eleven language editions. The original prompt data and original
locale dictionaries stay unchanged. Each README has one 40-cell, two-column
gallery at `static-examples`, with a full-image link and a matching localized
prompt link per cell. Each case page displays all of that case's supplied outputs
and links each preview to its own original image. Main and alternate labels
come from the example interface dictionary.

`assets/banner.png` is the shared repository banner. Every root README embeds
it once. Its native pixel dimensions preserve 5:2 proportions with integer-pixel
rounding; no per-language bitmap is generated. The banner's title is
`DTC Static ad Prompts Template`.

For a media update, retain immutable prompt bytes and stable case numbers.
Verify the complete case/output mapping, original-byte hashes, declared image
dimensions, public R2 readback, actual rendered preview/full-image links, and
all localized prompt destinations. Run the portable build and validator, inspect
desktop and narrow layouts, then obtain independent review and the repository's
original pre-push and post-push publication gates. Local script success does
not prove remote image bytes, translation fluency, or campaign performance.
